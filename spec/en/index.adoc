= FPSOT documentation specification
include::_fpsot-terms.adoc[]

This specification sets how {abbr-fpsot-first} specifications are documented, organized and published.
Officials can then compare any specification with the rules of their own government in the same way.

The rules come in six parts.

* xref:repository.adoc[Repository files] list what every specification repository holds.
* xref:pages.adoc[Pages] set the page types, the folder layout, diagrams and abbreviations.
* xref:organisation.adoc[Organization by jurisdiction] sets how each topic compares with the rules of each government.
* xref:sources.adoc[Outside sources] set how a specification summarizes and cites a standard it does not own.
* xref:versions.adoc[Versions and history] set what each page says about its own version.
* xref:outputs.adoc[Outputs] set the book view and the published formats.

The prose rules come from the {abbr-fpsot} writing specification.

== Conformance

[quote, 'link:https://www.rfc-editor.org/info/rfc8174[RFC 8174]']
____
The key words "MUST", "MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED", "NOT RECOMMENDED", "MAY", and "OPTIONAL" in this document are to be interpreted as described in BCP 14 (link:https://www.rfc-editor.org/info/rfc2119[RFC 2119], link:https://www.rfc-editor.org/info/rfc8174[RFC 8174]) when, and only when, they appear in all capitals, as shown here.
____

A specification repository conforms when it meets every MUST rule.
The doccheck tool and the jurisgen tool of the shared continuous integration test most of them.
